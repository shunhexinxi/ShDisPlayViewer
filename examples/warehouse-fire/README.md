# 城市火灾示例：仓库火灾协同处置演练

这是 ShDisplayViewer 的城市火灾示例，采用虚构桌面推演数据，使用现有动态演练播放器；不需要 IMS、设备账号或额外素材。默认地理锚点为东经 120.365、北纬 36.310。路线及点位覆盖约东西 22 公里、南北 13 公里；涉事仓库仍保持局部建筑尺度。所有园区、建筑、力量、道路及位置关系均为虚构，不声称该坐标实际存在仓库或消防设施。

## 播放

公开源码附带本目录的独立方案，名称为 **示例：城市火灾协同处置（虚构）**。通过“项目 → 导入 Qt 动态标记 XML…”选择本目录并保存到新的空项目，再配置自己的地图。选中方案，点击“播放”；支持暂停、上一步、下一步和时间轴定位。右键步骤或标记可查看、修改属性。按标记属性的“视角 → 获取当前视角”可以重新设置观察位置。

每个标记占 5 秒，包含 2 秒镜头飞行和 0.5 秒提示闪烁；总计 30 个标记、150 秒。顺序播放时，播放器采用当前标记保存的视角，所以每步第一个标记均配置了对应阶段的视角：发现报警近景、疏散区域、首批力量远景、到场近景、增援区域、协同区域、火情复核近景和全区复盘。点击“下一步”或从时间轴跳到其他步骤也会触发对应视角。播放时间是展示节奏，不是消防响应时限或真实处置耗时。实际报警、疏散与调派可并行，步骤排序仅用于讲解。

| 阶段 | 时长 | 地图表现 | 讲解或讨论重点 |
|---|---:|---|---|
| 01 发现报警 | 20 秒 | 初始火点、仓库轮廓、关注区、警情上报点 | 地点、人员、危险因素与接应信息是否清楚 |
| 02 疏散接应 | 20 秒 | 绿色疏散箭头、集合点、门岗、人员核对点 | 疏散和报警并行；人员信息如何闭环 |
| 03 首批力量前往 | 20 秒 | 蓝色出发点、折线箭头、途中节点、到场点 | 路线、联络、接应及到场信息交接 |
| 04 到场部署 | 20 秒 | 指挥点、作业区、供水核验点、入口管控线 | 分工、侦察信息与保障条件 |
| 05 请求增援 | 20 秒 | 紫色需求报告、增援出发点、路线、途中节点 | 报告任务与能力缺口，明确接应和联络 |
| 06 增援协同 | 20 秒 | 增援交接、医疗协同、装备保障、信息汇总点 | 任务交接及统一指挥 |
| 07 火情控制 | 15 秒 | 火情控制状态、现场复核、看护交接点 | 控制结论来自演练注入，继续核对尚存风险 |
| 08 清点复盘 | 15 秒 | 人员清点、装备交接、复盘点 | 对照报警、接应、增援、协同各环节查漏补缺 |

红色表示初始火情，橙色表示关注与管控，蓝色表示首批力量，紫色表示增援，绿色表示疏散与阶段结果，青色表示指挥和保障。

## 表达边界

播放器会累积保留历史标记，因此名称中的 01—08 是阶段编号。首批队伍的出发点、途中节点、到场点是同一过程的历史记录，不代表三支队伍同时驻留；末期仍可见的红色火点是初始记录。当前数据采用路线箭头、节点依次出现和视角飞行表达行进，不含车辆连续移动、道路导航、火势扩散或烟气计算。

图示范围没有进行安全距离计算；疏散点、水源点、医疗点和路线没有实地核查，广域箭头不能作为真实道路或行驶路线使用。用于真实单位演练时，应由该单位和专业人员按实际场地及预案调整。示例不规定内攻战术、灭火剂或医疗方法。未配置 RTSP、网页或程序关联动作，避免虚构设备地址和触发外部操作。

## 文件及复用

- `dynamic-plans.xml`：仅包含这一个方案，适合归档、审阅和导入。
- `generate.py`：Python 3.9+ 标准库生成器，同时检查 ID、坐标、点数和播放时长；只重写本目录示例 XML。
- `README.md`：本说明及讲解提纲。

运行项目中的演练数据位于 `Data/Config/dynamic-plans.xml`。不要直接用本示例 XML 覆盖含有其他方案的运行文件。

如需作为新项目导入，可在“项目”菜单使用现有旧部署数据导入功能，选择本目录并保存为新的空项目目录，然后配置地图服务。示例文件不包含内部地图地址。现场已配置的地图仍以 Release 项目的设置为准。

如需平移整套示意位置，可在本目录执行 `python generate.py --longitude 120.365 --latitude 36.310` 并替换坐标参数，再导入为新项目。平移不会自动匹配真实道路，图形大小也会随纬度变化。

流程编排参考了江苏省消防救援总队公开的[综合体火灾演练报道](https://js.119.gov.cn/202502/jsxfww-menu-gzdt_c_1318fb97821249a98eb3.html)中报警、疏散、调派、现场协作、保障及讲评的环节。此处的仓库情景、点位、人员任务和播放节奏是为软件演示另行编写的，不是该报道对应的真实预案。
