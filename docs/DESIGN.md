# 独立演练工程设计

## 确认的产品方向

用户群为直接使用演练软件的单位。免费客户端提供完整的基本方案编辑与演示，付费方向为行业功能定制和系统集成。FreeEarthSDK 是独立闭源组件，第三方产品集成另行授权；Viewer 启动和基本使用不设置授权验证。

演练表示按步骤、部署标记、展示时长与视角进行方案表达。当前没有物理推演、智能裁决、多人协同、服务端调度或 IMS 实时数据同步。

## 保留与拆除

| 功能 | 实现 |
| --- | --- |
| 动态步骤演练 | 保留原动态时序、逐标记到达/闪烁/停留、累计展示、暂停和时间轴跳转逻辑 |
| 方案制作 | 方案、步骤、标记属性及几何编辑，保留 XML 兼容性 |
| 地图与标绘 | SceneWidget + FreeEarthSDK；原标绘算法位于私有 SDK 内 |
| 地图配置 | 本地文件、HTTP TMS、`.earth` 配置；具体驱动以 SDK 构建和插件为准 |
| 关联动作 | 统一为单击触发 RTSP、网页、程序；旧 IMS 专用动作不执行 |
| 演示保护 | 建立项目临时副本；原项目不接受演示中的自动保存；可另存 |
| IMS 集成 | 未编译 API 会话、事件流、登录页、权限页、设备控制和执勤业务页面 |
| 旧绑定字段 | 为 XML 兼容保留部分字段；不请求 IMS，不显示实时值；属性编辑保存后清除标记绑定 |
| 辅助工具 | 保留视角、漫游、测量和环境；地图/模型资源可用性决定具体效果 |

## 模块关系

`MainWindow → ProjectStore / ZqbsPage → SceneWidget → FreeEarthSDK`

`ZqbsPage → MarkerActions → VideoSDK / 系统浏览器 / 系统进程`

客户端不依赖原 Qt 工程的构建目录，不包含 ClientSession。保留内部 `Zqxxxt` 命名空间只是减少拆分对已有逻辑的扰动，不表示运行依赖。

## 数据与生命周期

项目根目录有 `shdisplay-project.json`，版本为 1。业务 XML 放在 `Data/Config`，独立于原客户端。新建项目只产生虚构演练数据和空白地图。

标准配置按确切文件名读写。模型、图标等通过单文件导入登记到 manifest；项目复制只遍历这份清单，不遍历整个数据目录。外部 `.earth` 文件和大型地图数据集不内嵌，跨机器需重新配置。暂不提供单个压缩包项目格式。

演示模式先保存编辑项目，再克隆到临时目录；退出时销毁副本、重新打开编辑项目。“保存”只写当前副本，“另存为”才形成可继续编辑的独立项目。

自动漫游不打开外部程序或视频；需要操作者主动点击测试或标记。标记动作只响应单击，动态步骤的自动出现不会执行外部动作。

## 平台边界

Windows 使用 MSVC x64；Ubuntu 目标为 22.04 及以上 x86_64。程序路径分别保存，使用 `QProcess` 启动明确程序，不通过 shell 拼接执行。地图和视频使用相同客户端接口，但底层 DLL 与 `.so` 开发包必须分别构建并验证。

当前采用 Qt 6.11、OSG 3.6、osgEarth 3.8 与 FFmpeg 7，与已取得的代码接口一致。Ubuntu 不能直接假定系统默认开发包版本符合要求。跨平台源码路径已处理，Linux 二进制兼容性仍需 Ubuntu 环境验证。
